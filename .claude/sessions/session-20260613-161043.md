## Summary

Production HTTPS outage (~2 days) diagnosed and resolved via Netlify DNS migration. Site-config token system introduced for all site-wide URLs/emails. DNS/hosting fully documented.

## Decisions made

- **Migrated to Netlify-managed DNS** (`dns1-4.p03.nsone.net`). Hostinger is now registration-only. Root cause of outage: nameservers silently reverted to Hostinger parking NS around 2026-06-11 (reason unknown — domain was active and paid). With Netlify DNS, this class of outage cannot recur. Full zone transferred and verified before activation.
- **`scripts/site-config.js` is the single source of truth** for all site-wide URLs and emails. `{{site:KEY}}` tokens replace hardcoded values in templates. Enforced by check #9 in `scripts/check.js` — blocks commits with hardcoded LinkedIn or quiz URLs in templates.
- **Email was unaffected throughout the outage** — MX records were intact in the Hostinger zone the whole time. Inbound email routed normally.
- **`docs/tech-architecture/dns-hosting.md` is the DNS/hosting reference** — registrar, nameservers, full zone, SSL, email, Brevo, quiz, incident log. Never guess this again.

## Key findings

- Hostinger's current nameserver brand is `dns-parking.com` (confusing, not actually parking). The zone was intact with correct records throughout — the issue was purely at the NS level.
- HTTP (port 80) was serving correctly throughout; only HTTPS (port 443) was broken. The cert was valid in Netlify's system but out of sync with CDN nodes — the Netlify DNS migration forced a full re-provision.
- `quiz.accelerator-x.ai` runs on Vercel, CNAME to `12e065e68de4a0b8.vercel-dns-017.com`.
- `accelerator-x.ai` domain auto-renewal was OFF in Hostinger — needs to be enabled.
