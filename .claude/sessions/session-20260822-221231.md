### Decisions

- Rejected an early design for `injectMarked` that auto-detected and reproduced the END marker's indentation from the current file state. It looked elegant but broke on `build-testimonials.js`: that script's source partial (`_templates/homepage-testimonials.html`) has zero indentation before its markers, while the desired *output* has 10 spaces — the indentation is a caller-owned formatting decision baked into the old hardcoded literal, not a property of the surrounding file the utility can safely infer. Caught via the byte-diff check before ever proposing a PR, not by review.
- `onMissing: 'throw'` vs `'warn'` preserved as an explicit, visible per-call-site choice rather than picked as one "correct" default — the original two scripts made this choice deliberately differently (testimonials required, hero-media optional/conditional) and consolidating the *mechanism* shouldn't quietly consolidate that *policy* too.
- Did not attempt to fix #130 (the testimonials v1/v2 markup mismatch discovered while researching this ticket) in the same PR — a mechanism-only refactor must not change production visual output, and which markup should win is a real decision, not a mechanical fix.
